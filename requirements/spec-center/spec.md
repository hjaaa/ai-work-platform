# 规范中心 (Spec Center)

## 需求概述

在工作台左侧侧边栏的「技能和应用」和「新任务」之间新增「规范」入口，用于集中管理 UI/前端/后端开发规范文件。

---

## 功能范围

### F1：规范文件管理（CRUD）

| 操作 | 说明 |
|------|------|
| 创建 | 填写规范名称 + 描述类型（UI/前端/后端），编辑 Markdown 内容 |
| 查看 | 列表 + 内容预览 |
| 编辑 | 修改名称、类型、Markdown 内容 |
| 删除 | 软删除；若已关联项目，同步删除对应磁盘文件 |

**约束**：
- 文件格式仅支持 Markdown
- 规范类型：UI、前端、后端（三选一，支持后续扩展）

---

### F2：规范关联项目

| 操作 | 说明 |
|------|------|
| 关联 | 将一条规范关联到指定项目 |
| 解除关联 | 解除后删除对应磁盘文件，并从 CLAUDE.md 中移除引用 |

**关联动作（服务端执行）**：
1. 将规范内容写入 `{project.codePath}/rules/{specId}.md`
2. 在 `{project.codePath}/CLAUDE.md`（不存在则创建）追加以下内容：

```
## 开发规范（自动注入，请勿手动删除）

在进行 UI 设计、前端开发、后端开发过程中，必须遵循以下规范文件：
- rules/{specId}.md：{specName}
```

> 若 CLAUDE.md 中已存在该规范的引用行，跳过（幂等）。

**文件操作顺序**：先写磁盘，成功后写 DB，失败则抛出异常阻止 DB 提交。

---

## 界面位置

工作台左侧侧边栏，顺序：

```
新任务
规范          ← 新增
技能和应用
（项目列表）
```

---

## 边界与约束

1. `project.codePath` 为空时不允许关联（提示用户先完成项目克隆/配置）
2. 同一规范可关联多个项目（N:M 关联表）
3. 关联记录不重复插入（幂等）
4. 删除规范时若存在关联，需先解除所有关联再删除（或级联删除）

---
